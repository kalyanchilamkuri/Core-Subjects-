# System Calls and Components of an Operating System

## 1. User Mode

- User mode is where regular applications like browsers and games run.
- Applications do not have direct access to hardware or critical system resources.
- If an application needs to access hardware (e.g., read from a disk), it requests the OS through **system calls**.
- A crash in user mode generally does not affect the entire operating system.

## 2. Kernel Mode

- Kernel mode is where the kernel runs.
- It has full control over hardware and system resources.
- It executes critical functions such as:
  - Process management
  - Memory allocation
  - File system management
  - I/O operations

**Important:** A bug in kernel mode can crash the entire operating system.

## 3. Switching Between User Mode and Kernel Mode

When a program needs to perform a privileged operation, such as reading a file:

1. The program makes a system call.
2. The CPU switches from user mode to kernel mode.
3. The OS handles the request.
4. After completing the operation, the CPU returns to user mode.
5. The program continues its execution.

### User Mode vs Kernel Mode

| User Mode | Kernel Mode |
|---|---|
| Runs regular applications. | Runs the kernel. |
| Has limited access to system resources. | Has full access to hardware and resources. |
| Cannot directly perform privileged operations. | Can perform privileged operations. |
| Application crashes usually do not affect the whole OS. | A kernel bug can crash the whole OS. |
| Uses system calls to request OS services. | Handles system call requests. |

**Real-life analogy:**
- **User Mode:** Like using a phone in a safe environment without access to its internal components.
- **Kernel Mode:** Like being a phone technician who can access the internal components but can also damage them.

## 4. Shell

- A shell, also known as a **command interpreter**, receives commands from users and gets them executed.
- It acts as an interface between the user and the operating system.

## 5. Kernel

- The kernel is the core part of the operating system.
- It runs in kernel mode and directly manages hardware and system resources.
- It is like the brain of the operating system.

### Functions of the Kernel

#### 1. Process Management

- Handles the creation, scheduling, and termination of processes.
- Keeps track of process states:
  - Ready
  - Running
  - Waiting
- Allocates CPU time to processes using scheduling algorithms such as Round Robin and FCFS.

**Example:** When a browser and a video editor are open at the same time, the kernel decides which process gets CPU time.

#### 2. Memory Management

- Controls how RAM is allocated to processes.
- Handles virtual memory, paging, and segmentation.
- Prevents one process from accessing another process's memory.

**Example:** If Chrome uses 2 GB RAM and VS Code uses 1 GB RAM, the kernel manages their memory and ensures they do not overlap.

#### 3. File System Management

- Manages reading and writing files to disk.
- Keeps track of file metadata such as name, location, and size.
- Handles file permissions and access control.

**Example:** When we save a file in Word, the kernel helps the OS store the file on disk.

#### 4. Device Management / I/O Control

- Manages I/O devices such as keyboards, mice, disks, and printers.
- Uses device drivers to communicate with hardware.
- Handles interrupts generated by hardware.

**Example:** When we connect a USB device, the OS uses the appropriate driver to communicate with it.

#### 5. System Call Interface (User ↔ Kernel Communication)

- Provides a way for user programs to request services from the kernel.
- These requests are made using system calls.
- Examples include `read()`, `write()`, and `fork()`.

**Example:** When a C++ program writes data to a file, it uses a system call to request the operation from the kernel.

#### 6. Security and Protection

- Prevents one user or process from interfering with another.
- Enforces access permissions for memory, files, and devices.
- Implements user mode and kernel mode rules.

**Example:** A normal application cannot access another application's private data unless the OS allows it.

## 6. System Calls

- A **system call** is a mechanism through which a user program requests a service from the operating system kernel.
- Applications use system calls to perform operations that require OS privileges.

### Examples of System Calls

| System Call | Purpose |
|---|---|
| `read()` | Reads data from a file or input source. |
| `write()` | Writes data to a file or output source. |
| `fork()` | Creates a new process. |

### Working of System Calls

1. A program running in user mode requests an OS service.
2. It makes a system call.
3. The CPU switches to kernel mode.
4. The kernel performs the requested operation.
5. The result is returned to the program.
6. The CPU switches back to user mode.

### Why Are System Calls Needed?

- Allow applications to access OS services.
- Provide controlled access to hardware and system resources.
- Prevent applications from directly performing privileged operations.
